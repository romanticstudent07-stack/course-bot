## 7. Контракт
- Шаблон ключа в API = шаблон СХЕМЫ (константа KEY_PATTERN в app/texts.py, одна на API и загрузчик).
- GET /miniapp/v1/texts/{key}: 200 {key, tone, legal_status, text, plurals_ru | null} (notes НЕ отдавать);
  404 TEXT_NOT_FOUND; 422 — ключ не по шаблону; 401 — из роутера; 503 SERVICE_UNAVAILABLE — БД недоступна.
- POST /miniapp/v1/texts/bulk: тело {keys: [str]} — 1..100 штук, каждый по шаблону; дубли схлопнуть.
  200 {texts: [как выше, в порядке запроса], missing: [key]}; 422 — пусто, > 100 или плохой ключ.
- Функция чтения — get_texts_for_participant (И4: рендер разделён по аудитории; других аудиторий пока нет).
- Загрузчик: `python -m app.texts load` (из /app в контейнере). Читает все apps/api/config/texts/*.json,
  проверяет каждый файл схемой (jsonschema, Draft 2020-12), ищет дубли ключей между файлами.
  Ошибка → exit 1, в БД ничего не пишется. Успех → одна транзакция INSERT … ON CONFLICT (key) DO UPDATE,
  registry_version = version файла. Ключи, которых нет в файлах, не удалять — только вывести списком.
  Вывод: «загружено N, обновлено M, лишних в БД K».
- Seed B4.json: version "0.1.0", owner_block "B9", durability_block "B14", tone neutral,
  legal_status pre-legal-review, текст «[ЗАГЛУШКА] …». Ключи (4): B4.onb_welcome, B4.onb_age_gate,
  B4.onb_age_underage, B4.onb_done. legal.json — НЕ в этой задаче (создаёт 1e-1).
