## 4. Выдержки и факты (исследование сделано, КОДЕРУ не повторять)
Архитектура:
- errata-unified E1: «Запись разрешена только роли participant_state_projector, чтение — participant_state_reader».
- I2 read_only_enforcement: «must use reader role except in Б10 projector process».
- D-13: «отдельная роль приложения с минимальными GRANT (tg_user_registry: SELECT, INSERT; participant_state:
  только через reader/projector)». Дополнение про UPDATE (created_via) внесёт ШТАБ при закрытии B-3.
- 0001_init: participant_state_projector — INSERT, UPDATE ON participant_state; participant_state_reader — SELECT;
  роли кластерные, создаются DO-блоком IF NOT EXISTS, downgrade их не удаляет.
Postgres:
- SELECT … FOR UPDATE (как и любая блокировка строк) требует права UPDATE хотя бы на одну колонку таблицы.
- RETURNING, WHERE и ON CONFLICT требуют SELECT на упомянутые колонки.
- SQLAlchemy 2.0 сам добавляет RETURNING id к одиночному INSERT в таблицу с bigserial.
- short_no (GENERATED ALWAYS AS IDENTITY) — права на последовательность не нужны; bigserial — USAGE на <таблица>_id_seq.
- Проверка FK идёт от владельца таблицы; pg_advisory_lock доступен PUBLIC; CONNECT к БД и USAGE схемы public
  у PUBLIC есть (postgres:16).
- На tg_user_registry триггеров нет: 0002 создаёт только таблицу и частичный индекс tg_user_registry_active_tg_user_uidx, 0001 и 0003–0005 триггеров не создают.

SQL → право (сверено по коду 90f7df2):

| Кто | SQL | Право |
|---|---|---|
| first-launch | SELECT text_registry (тексты C0, C1) | SELECT text_registry |
| first-launch | INSERT tg_user_registry … ON CONFLICT DO NOTHING RETURNING pid, short_no | INSERT, SELECT |
| first-launch, повтор | SELECT pid, short_no … WHERE tg_user_id, tombstoned_at IS NULL FOR UPDATE | SELECT + UPDATE (created_via) |
| first-launch | SELECT consent_events (kind, action, text_key, text_snapshot) | SELECT |
| first-launch | INSERT consent_events (RETURNING id) | INSERT, SELECT, USAGE consent_events_id_seq |
| first-launch | INSERT participant_events (RETURNING id) | INSERT, SELECT (id), USAGE participant_events_id_seq |
| status, GET /consents | SELECT tg_user_registry (без блокировки), consent_events, text_registry | SELECT |
| /texts | SELECT text_registry | SELECT |
| проектор | pg_advisory_lock / unlock, SELECT 1 | не нужно |
| проектор | SELECT participant_events e LEFT JOIN participant_state_checkpoints c | SELECT обеих |
| проектор | INSERT participant_state … ON CONFLICT (pid) DO UPDATE … WHERE lifecycle_phase … RETURNING pid | projector + reader |
| проектор | INSERT checkpoints … ON CONFLICT DO UPDATE SET last_event_id = GREATEST(…), at | SELECT, INSERT, UPDATE (last_event_id, at) |

POST /consents в 90f7df2 нет. Почему UPDATE (created_via): CHECK разрешает одно значение
('mini_app_first_launch') → изменить данные API не может; pid, short_no, tg_user_id, tombstoned_at, created_at — нельзя.

  тело {"birth_date": "1990-01-01", "consents": ["C0", "C1"]} → 201 {pid, short_no}; повтор → 201, тот же pid.

- Маршруты берут engine через app.db.session.get_engine(settings) → _engine_for(dsn) (lru_cache по DSN).
