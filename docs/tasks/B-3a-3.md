## 7. Контракт
compose, сервис projector: env_file убрать; environment ровно:
    environment:
      PROJECTOR_DATABASE_URL: ${PROJECTOR_DATABASE_URL}
      LOG_LEVEL: ${LOG_LEVEL:-INFO}
      TZ: ${TZ}
compose, сервис bot: env_file убрать; environment ровно:
    environment:
      BOT_TOKEN: ${BOT_TOKEN}
      WEBAPP_URL: ${WEBAPP_URL}
      LOG_LEVEL: ${LOG_LEVEL:-INFO}
      TZ: ${TZ}
Если у сервиса уже есть environment (например TZ) — слить, не дублировать. Прочие ключи сервисов (build/image,
command, depends_on, networks, restart, deploy.limits, healthcheck) — как были. Сервис api не трогать.
Комментарий в шапке compose: почему у projector и bot нет env_file (B-3; новые переменные им — только явно).
.env.example — новый блок рядом с PostgreSQL (DATABASE_URL уже упомянут → не дублировать):
    # --- Роли БД (B-3): пусто → всё как до B-3 (DSN из POSTGRES_*) ---
    # DATABASE_URL — API (coursebot_api, роль app_api).
    # PROJECTOR_DATABASE_URL — проектор (coursebot_projector, роль app_projector); у контейнера projector
    #   это единственный путь к БД (env_file нет).
    # MIGRATIONS_DATABASE_URL — alembic и python -m app.texts load (владелец, POSTGRES_USER).
    # Формат: postgresql+psycopg://<пользователь>:<пароль>@db:5432/<POSTGRES_DB>
    # Пароли — openssl rand -hex 24 (только 0-9a-f, экранировать не нужно).
    DATABASE_URL=
    PROJECTOR_DATABASE_URL=
    MIGRATIONS_DATABASE_URL=
SERVER-IRONCLAD.md:
- раздел «Роли БД (B-3)»: роли app_api / app_projector (миграция 0006, NOLOGIN); пользователи coursebot_api /
  coursebot_projector создаются вручную (CREATE ROLE … LOGIN IN ROLE …, \password), пароли только в .env;
  какая переменная у какого процесса; alembic и загрузчик текстов — под MIGRATIONS_DATABASE_URL (владелец);
  правило: каждая миграция с новой таблицей выдаёт GRANT ролям app_api / app_projector в той же миграции;
  у projector и bot нет env_file — новая переменная им добавляется в environment явно;
  `docker compose config` и `env` контейнера целиком в чат не выводить (там пароли).
