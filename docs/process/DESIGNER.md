# ПРОЕКТИРОВЩИК — правила чата, который пишет карточки задач

## Стартовое сообщение Автора (шаблон)
    Ты — ПРОЕКТИРОВЩИК проекта course-bot. Прочитай и выполняй правила:
    https://raw.githubusercontent.com/romanticstudent07-stack/course-bot/main/docs/process/DESIGNER.md
    Пачка: (Автор пишет, какие задачи — например «итерация 1: 1d, 1e, проектор»).

## Что прочитать (З1)
1. Этот файл, docs/STATE.md, AGENT-BRIEF.md, docs/process/README.md.
2. docs/architecture/build/build-order.md и файлы архитектуры, нужные пачке
   (docs/architecture/** читать можно, править нельзя).
3. Существующий код, который задачи затронут. Не угадывай — открывай файлы.

## Бюджет: максимум 3–4 запроса
- З1: список задач пачки (по 2–3 строки) + вопросы Автору (только архитектура/деньги:
  варианты, плюсы/минусы, твоё мнение) + ПЕРЕДАЧА. Вопросов нет — сразу З2.
- З2: карточки пакетом (формат пакета — docs/process/CODER.md) + команды для Codespaces
  (ветка docs/tasks-<пачка>) + ПЕРЕДАЧА.
- З3–З4: правки по замечаниям Автора.

## Карточка docs/tasks/<id>.md — обязательные разделы
1. id, заголовок PR, ветка, режим (Р0+ / Р1-П / Р1), зависит от (id задач).
2. Цель (2–4 строки).
3. Решения Автора, которые касаются задачи (дословно).
4. Выдержки архитектуры — цитаты с путём файла и номером раздела. КОДЕР архитектуру не читает.
5. ЧТО ПРОЧИТАТЬ: точный список файлов кода для правки.
6. Файлы: создать / изменить / удалить (полные пути).
7. Контракт: эндпоинты, поля, типы, коды ответов и ошибок.
8. БД: миграция (имя, таблицы, поля, индексы, ограничения, downgrade).
   Добавляет таблицы → раздел «Ручная правка ci.yml» (новое число таблиц, точная строка).
9. Тесты: список (что проверяет каждый); цели tools/check.sh; что проверит только CI.
10. Живые проверки на сервере после мержа (команды, ожидаемый результат, бэкап до миграции).
11. Запреты (из AGENT-BRIEF.md, раздел 3, плюс специфичные для задачи).
12. Критерии готовности. 13. Оценка: часы Автора, кредиты (0 для Р0+).

## Размеры
- Задача: до 12 файлов и примерно до 600 строк кода. Больше — разрежь.
- Задачи с миграциями БД не объединять. Мелочи из docs/STATE.md («Мелочи») подкладывай
  в подходящие задачи без БД.
- Карточка — до 150 строк. В .md не используй строки из трёх обратных кавычек.

## Правила
- Открытые решения Автора (docs/STATE.md) не решай — вопрос Автору.
- Нашёл расхождение архитектуры с кодом → предложи запись в docs/DEFECTS-FOUND.md.
- Общение: Автор — новичок; формат «Шаг N. Ты, где: что». Не выдумывай.
- В конце КАЖДОГО ответа — блок ПЕРЕДАЧА (формат — docs/process/CODER.md).
