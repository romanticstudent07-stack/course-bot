## 5. Правило «0 ПОТЕРЬ» и память проекта
1. Промпты, файлы, комментарии, задания серверу — ВСЕГДА целиком, одним блоком.
   Запрещено: «…», «см. выше», «остальное без изменений», «вставь сюда …».
2. Правка файла — полный новый текст. Огромный файл (например ci.yml) → точная инструкция
   «найди эту строку целиком → замени на эти строки целиком» с объяснением почему.
3. Текст из PR (ci.yml и т.п.) ШТАБ достаёт сам, сверяет с main и отдаёт целиком.
4. Важные тексты не цитируются по памяти: перед выдачей перечитать источник.
   Источник недоступен или пришёл обрезанным → сказать прямо и попросить.
5. История сжалась, нужного текста нет → сразу «пришли мне X», не восстанавливать.
6. Где что живёт:
   - docs/process/SHTAB.md (часть 1, разделы 0–3) и docs/process/SHTAB-2.md
     (часть 2, разделы 4–9) — правила ШТАБа; docs/process/README.md — процесс v2;
     CODER.md, DESIGNER.md, SERVER.md — правила ролей;
   - docs/STATE.md — живое состояние: hash main, смержено, решения, очередь, мелочи,
     дефекты, открытые решения, учёт кредитов;
   - docs/HISTORY.md — подробности закрытых задач, решения по процессу, уроки;
   - docs/tasks/<id>.md — карточки задач;
   - у Автора на компьютере (папка проекта):
     SHTAB-CONTEXT-CHAT.txt — 1 старт, 2 ПЕРЕДАЧА, 3 отчёт сервера, 4 последний промпт
     Агенту, 5 последний ответ Агента;
     SHTAB-копия-1.md и SHTAB-копия-2.md — копии обеих частей правил (на случай, если
     ссылка не откроется или файл придёт обрезанным);
     start-ПРОЕКТИРОВЩИК.txt и другие стартовые сообщения; промпт серверного чата;
     папка archive (старые версии, ничего не удалять).
     Секреты, IP, хосты — только у Автора, в репо никогда.
7. Меняешь эти правила → сравни со старой версией и перечисли, что добавлено и что
   изменено. Удалять пункты без согласия Автора нельзя.
8. ПЕРЕДАЧА — короткая записка «на чём остановились» для нового окна ШТАБа на случай
   сжатия. В конце КАЖДОГО ответа ШТАБа, СТРОГО до 8 строк, по порядку:
   hash main и состояние сервера; текущая задача и шаг; что ждём от Автора; решения
   этого ответа; открытые долги; дальше по очереди.
   Разрослась больше 8 строк → ШТАБ сам вычёркивает закрытое и переносит подробности
   в строки для docs/STATE.md, а не в ПЕРЕДАЧУ. ПЕРЕДАЧА — не журнал проекта.
   ПЕРВАЯ СТРОКА блока всегда говорит Автору, что делать:
   «ПЕРЕДАЧА — ничего делать не нужно» или
   «ПЕРЕДАЧА — замени раздел 2 в SHTAB-CONTEXT-CHAT.txt этим блоком»
   (второе — после закрытой задачи или при признаках сжатия).
9. Чтение репо (репо публичный):
   1) https://raw.githubusercontent.com/romanticstudent07-stack/course-bot/<hash или main>/<путь>
   2) https://api.github.com/repos/romanticstudent07-stack/course-bot/contents/<путь>?ref=<hash>
   3) попросить Автора вставить файл.
   Важные тексты (правила, карточки, код для правки, ci.yml) — по hash коммита, не по
   main: raw для main бывает старым (особенно до 5 минут после мержа).
   HTTP 416 при чтении кусками значит «файл кончился», это не ошибка.
   docs/architecture/** — только нужный раздел, не целиком.
   Приоритет правил: промпт задачи > AGENT-BRIEF.md > AGENTS.md / CONTEXT.md.
10. ОБРЕЗКА ЧТЕНИЯ — главный риск потерь. Чтение ссылки рубится примерно на 10 000
    токенов, и обрезанный файл выглядит целым. Поэтому:
    - файлы правил и карточки держим меньше ~7 000 токенов каждый; вырос больше —
      делим на части с метками «КОНЕЦ ЧАСТИ N из M» или выносим в docs/HISTORY.md;
    - у каждого делимого файла ссылки на остальные части стоят в ПЕРВЫХ строках,
      чтобы их не срезало;
    - прочитал файл и не увидел ожидаемую последнюю строку (метку конца, закрывающую
      скобку, последний раздел) → считай файл неполным и скажи об этом Автору сразу;
    - diff PR тоже обрезается: не увидел хвост — читай полные файлы по hash головного
      коммита PR и честно напиши, что смотрел.

Telegram-курс личной трансформации: Mini App + бот + backend. Mini App-first.
React 18 + Vite + TS (apps/miniapp, nginx), Python 3.12 + aiogram 3 (apps/bot),
FastAPI + PostgreSQL 16 + Redis 7 (apps/api), S3 — Garage (dev).
Панель Автора (Блок 17) — только в боте. Оплата — ВНЕ Mini App.
Репо проекта: https://github.com/romanticstudent07-stack/course-bot — ПУБЛИЧНЫЙ до

в репо — только заглушки до 0-Б.
Защита main (Settings → Rules → Rulesets): main-branch-protection — только через PR,
запрет удаления и force-push, обход — только Автор; main-ci-lock — 7 проверок CI
обязательны, обхода нет. PR из форков запускают CI только после одобрения Автора.
Репо архитектуры: DOCS-course-bot (приватный). docs/architecture/ — READ-ONLY зеркало
(sync-architecture.yml, guard в CI). Расхождения → docs/DEFECTS-FOUND.md.
В main — только через PR. Секреты — только в .env на сервере.
Правила Агента: AGENT-BRIEF.md, AGENTS.md, .genspark/rules.md.
Итерации (docs/architecture/build/build-order.md): 0-А локальная инфра → 1 онбординг
→ 2 дневной модуль → 3 Чек-Ап и Карточка → 4 оплата/refund → 5 фото и хранение →
6 Панель Автора; 0-Б переезд на облако.

Пересмотр плана — 01.11.2026.
GitHub App Genspark НЕ имеет права workflows (и не получит — решение Автора):
.github/** правит только Автор вручную на сайте github.com.

cd ~/course-bot && docker compose --env-file .env -f infra/docker-compose.dev.yml …

Чужие контейнеры maxmover и tg_vk и чужой cloudflared — не трогать.

## 8. Уроки (не повторять; подробно — docs/HISTORY.md)

  задания «до мержа» / «после мержа»; без плейсхолдеров; контейнеры без нужды не
