2. Лист решений Автора на итерацию — одно окно ИССЛЕДОВАНИЕ, ответы Автора разом.

## 4. Выкат по необходимости
Выкат нужен, если есть хотя бы одно:
- живая проверка вне CI (доставка в Telegram, ночное закрытие, лестница, темы группы);
- баг в выкаченном коде задевает тестовые дни А1–А3;
- следующей задаче для живой проверки нужна миграция или сервис на сервере;
- конец итерации или общая живая сессия.
Не нужен: docs, карточки, код без живой проверки — лежат в main и ждут.
Против ошибок:
- «Очередь выката» ведётся здесь (ниже), с недельным docs-пакетом переносится в STATE: PR → сервисы, миграция, строки .env, нужна ли живая проверка.
- Задание серверу строится по очереди + git diff --stat <hash сервера>..main, не по памяти (урок 01.11).
- Миграции — по одной, с проверкой после каждой.
- Менялись и api, и bot — пересобираем в одном выкате.
- Наблюдения (ночь, пуши, обрывы) — в Г0 ближайшего выката, отдельным заданием не носить.
Очередь выката на 01.11: пусто (всё до e881d07 на сервере).
