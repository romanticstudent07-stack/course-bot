# Процесс v2 «Синергия» — как делаем course-bot

Принят 27.09.2026, уточнён 01.10.2026 (v3.4). Цель: всё до итерации 6 + переезд на VPS (0-Б).
Сроков нет: сначала правильная настройка. Думают и пишут код бесплатные чаты
Claude Opus 5.5 (Genspark AI Chat). Тесты — Codespaces (быстрые) и CI (все, включая БД).
Платный агент — исключения и важные задачи на свободный остаток кредитов.

## Роли (все чаты — Opus 5.5)
- Автор: вставляет пакеты, запускает команды, открывает и мержит PR, принимает
  архитектурные и денежные решения.
- ШТАБ (главный, docs/process/SHTAB.md): процесс, очередь, учёт, стартовые сообщения
  другим чатам, проверка их результата, закрытие задачи (проверка PR, комментарий,
  мерж, задание серверу, строки для STATE.md).
- СЕРВЕРНЫЙ (постоянный, один, свой промпт у Автора; интерфейс — docs/process/SERVER.md):
  всё на IRONCLAD. Задания получает от ШТАБа.
- ПРОЕКТИРОВЩИК (docs/process/DESIGNER.md): временное окно на пачку 3–5 карточек задач.
- КОДЕР (docs/process/CODER.md): временное окно на КАЖДУЮ задачу.
- РЕВЬЮЕР (временное окно, с задач B-2 и 1e): свежий взгляд только на PR про безопасность
  (initData, 18+, B-1, B-2, B-3, оплата). Одно окно на один PR. Стартовое сообщение даёт
  ШТАБ, вывод РЕВЬЮЕРА проверяет ШТАБ. Нужен ли — раздел 14 карточки.
- Codespaces: раскладка пакета (tools/unpack.py) и быстрые тесты (tools/check.sh).
- CI: 7 проверок на каждый PR (тесты с БД, сборка Docker, guard с проверкой eol).
  Все 7 обязательны технически (ruleset main-ci-lock): красный PR смержить нельзя.
- Агент Genspark (кредиты): режимы Р1-П и Р1.

## Лестница способов (от дешёвого к дорогому)
- Р0 «Сайт»: 1–3 файла без логики, .github/** → сайт GitHub. 0 кредитов.
- Р0+ «Пакет» (ОСНОВНОЙ): КОДЕР пишет пакет → Codespaces: unpack → check → push → PR → CI.
- Р1-П «Агент-раскладчик»: тот же пакет + короткий промпт агенту (AGENT-BRIEF.md, раздел 11).
  Когда: пакет больше 12 файлов; 2 круга красного CI без понятной причины; у Автора нет времени.
- Р1 «Агент-исполнитель»: только если задачу нельзя описать карточкой.
- Запасной: кончилась квота Codespaces → Р0 через github.dev / vscode.dev (до 6 файлов) + CI.
  Эти редакторы пишут CRLF — CI guard это поймает, починка в Codespaces:
  git add --renormalize . && git commit -m "chore: LF" && git push.

## Жизнь чатов
- ШТАБ и серверный чат работают в одном окне, пока история не сжалась.
  Сжалась → новое окно со своим файлом восстановления у Автора. Сообщения не считаем:
  файл Автора обновляется после каждой закрытой задачи, поэтому сжатие ничего не теряет.
- КОДЕР — до 3 запросов Автора, ПРОЕКТИРОВЩИК — 3 запроса (DESIGNER.md), потом новое окно.
- Каждый ответ любого чата заканчивается блоком ПЕРЕДАЧА (до 8 строк); первая строка
  говорит Автору, что с ним делать. Новое окно стартует с этого блока — ничего не теряется.
- Тяжёлые запросы (пакеты) — в начале 5-часового окна лимита (лимиты общие на все чаты).
  Лимит кончился → Автор делает ручную часть (Codespaces, сервер, мерж), не ждёт.

## Память проекта (в репо, читается чатами по ссылкам)
- docs/STATE.md — состояние. docs/HISTORY.md — подробности прошлого.
- docs/tasks/<id>.md — карточки задач. docs/process/*.md — правила чатов.
- AGENT-BRIEF.md — факты и запреты проекта.
- Чтение: https://raw.githubusercontent.com/romanticstudent07-stack/course-bot/<hash>/<путь>
  Важные тексты (правила, карточки, код для правки) — по hash коммита, а не по main:
  raw для main бывает старым. Hash main — в docs/STATE.md или в стартовом сообщении.
  → не открылось: https://api.github.com/repos/romanticstudent07-stack/course-bot/contents/<путь>?ref=<hash>
  → не открылось: попросить Автора вставить файл. По памяти не восстанавливать.

## Codespaces
- Тип 2-core. После работы — Stop (github.com/codespaces → «…» → Stop codespace).
- Idle timeout минимальный, хранение 7 дней. Квоты 60 ч/мес на 2-core хватает на 30+ задач.
- Разовая настройка уже сделана: git config core.hooksPath .githooks.

## Размеры
- Одна задача = один PR: до 12 файлов и примерно до 600 строк кода. Больше — две задачи.
- Задачи с миграциями БД не объединять и не вести параллельно: следующая задача с миграцией
  стартует после мержа предыдущей (иначе у Alembic две «головы» — две ветки миграций).
  Мелочи без БД — объединять.
- Миграция добавляет или удаляет таблицы → в том же пакете apps/api/tests/expected_tables.txt
  с полным новым списком (по нему CI сверяет БД). ci.yml не трогаем.
- Новый файл *.sh → право на запуск: chmod +x <файл> до git add (tools/check.sh проверяет).

## Кредиты
- Тариф Plus 10 000/мес, обновление 25-го, остаток сгорает. Резерв 1 500.
  С 20-го по 24-е свободный остаток — агенту на важные задачи (решает ШТАБ с Автором).
- Учёт каждой задачи: режим / оценка / факт / часы Автора — в docs/STATE.md.

## Публичный репо
- Считаем, что всё в нём публично навсегда: форки и кэши ИИ останутся и после перевода
  репо в приватный. Никаких реальных Telegram ID, IP, имён хостов, ПДн.
- Тексты курса (дни, задания, сообщения бота) — только заглушки до 0-Б.
- Secret scanning + Push protection включены. Логи CI видны всем — env не печатать.
- PR из форков: CI запускается только после одобрения Автора (Settings → Actions).

## Стоп-правила
- Одна и та же ошибка 2 раза → третья попытка последняя → дальше Р1-П или ШТАБ.
- unpack отклонил пакет → текст ошибки назад в КОДЕР, скрипт не обходить.
- Красный CI и вопросы без ответа — не мержим. Сервер — только main.
