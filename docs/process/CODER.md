## Бюджет: максимум 3 запроса Автора
- Запрос — только сообщение Автора с новым содержанием (лог, ошибка, ответ, вопрос).
  «Далее» и «Повтори часть k» в бюджет 3 запросов НЕ считаются (правила выдачи — PACK.md, раздел 2).
- З1: план пакета + части 1–2. План задачи не пересказывай — карточка уже утверждена.
- «Далее» → следующие части (не больше 2 за ответ), пока пакет не кончится.
- «Повтори часть k» → часть k ЦЕЛИКОМ заново под тем же номером.
- З2: исправление по логу.
- З3: исправление по логу (последняя попытка по одной и той же ошибке).
- ИТОГ ДЛЯ ШТАБА (решение Автора 06.11) — в КОНЦЕ ответа с последней частью пакета (З1, З2 или З3),
  сразу под шагами и текстом PR. Номер PR и итог CI НЕ ждать и НЕ просить. Дальше Автор:
  CI зелёный → несёт в ШТАБ ИТОГ, номер PR и итог CI («N из N зелёные»);
  CI красный → несёт лог сюда (З2/З3), КОДЕР выдаёт исправление и ИТОГ заново.
  Закрытие задачи (проверка PR, комментарий, мерж, задание серверу) делает ШТАБ, не КОДЕР.
- Не уложились → ИТОГ со строкой «Состояние: не закончено» (PACK.md, раздел 6), Автор открывает новое окно КОДЕР.

## Пакет КОДЕРА (сверх PACK.md, раздел 2)
- Первый файл пакета З1 — docs/STATE.md с внесёнными строками от ШТАБа.
  Строк нет — STATE.md не трогай.
- Нужна правка .github/** → отдельный блок «ДЛЯ РУЧНОЙ ПРАВКИ» с полным текстом файла
  и списком отличий от main (Автор вносит сам через сайт). Имена job в ci.yml не менять:
  это имена обязательных проверок (ruleset main-ci-lock).
- Миграция добавляет или удаляет таблицы → в пакет apps/api/tests/expected_tables.txt
  целиком, с полным новым списком. ci.yml не трогаем.
- Новый файл *.sh → строка chmod +x в шаге 3 (PACK.md, раздел 5); check.sh проверит.
- Тексты курса (дни, задания, сообщения бота) — только заглушки: репо публичный.
- Новые зависимости — только если есть в карточке.
