# PACK — формат пакета, шагов и ответа окна (решение Автора 12.11.2026)
Для окон КОДЕР, ПРОЕКТИРОВЩИК, ИССЛЕДОВАНИЕ. Где этот файл расходится с CODER.md или DESIGNER.md — верен этот файл.
Первая строка З1 окна: «PACK.md: метка конца есть». Метки нет — сказать Автору и работу не начинать.

## 1. Чтение
- Файлы репо — по hash из старта: https://cdn.jsdelivr.net/gh/romanticstudent07-stack/course-bot@<hash>/<путь>. Только по hash, @main запрещён.
- Запасной путь — raw.githubusercontent.com по тому же hash: только если jsdelivr не открылся или файл пришёл без ожидаемой последней строки.
- Файл пришёл с пропуском или без конца — сказать Автору сразу и дочитать целиком до любого вывода.
- Читать только список из старта. Прочитанное целиком в этом окне повторно не читать.
- docs/STATE.md КОДЕР читает, только если ШТАБ дал строки для STATE. Hash main — из старта.
- Размеры файлов — из старта или карточки; запросами к api.github.com не узнавать.

## 2. Пакет
- Часть — ОДИН блок кода с языком text. Внутри только блоки:
      ===== FILE: путь/от/корня/репо =====
      полный текст файла
      ===== END =====
      ===== DELETE: путь/от/корня/репо =====
- Файл — ЦЕЛИКОМ, одним блоком; между частями не делится.
- В начале З1 — план: «Пакет: N частей. Часть 1: <файлы>; часть 2: <файлы>». Номера и состав частей потом не меняются.
- Последняя строка ВНУТРИ блока части: «КОНЕЦ ЧАСТИ k из N: файлов M». Нет строки — часть оборвалась.
- В одном ответе не больше 2 частей, затем стоп и строка «Части 1–2 из N готовы. Напишите: Далее». Часть — примерно до 350 строк.
- «Повтори часть k» — часть k ЦЕЛИКОМ заново под тем же номером. Никаких «частей N+1» как исправлений и пояснений вместо файлов.
- После последней части строка: «КОНЕЦ ПАКЕТА: частей N, файлов M».
- В .md внутри пакета нет строк из трёх обратных кавычек: примеры кода — отступом 4 пробела. Файл обязан содержать такие строки — часть выдаётся в блоке из ЧЕТЫРЁХ обратных кавычек, файл буква в букву.
- Разрешённые пути — как в tools/unpack.py. Нельзя: docs/architecture/**, .github/**, .githooks/**, .env.

## 3. Памятка unpack
tools/unpack.py отклоняет пакет целиком из-за заглушек в ЛЮБОМ файле, и в .md тоже (комментарии тестов, заметки, описания).
(1) Строка целиком, после обрезки пробелов по краям, равна одному из: «...», «…», «# ...», «# …», «// ...», «// …», «/* ... */», «<!-- ... -->».
(2) В строке, без учёта регистра, есть: «остальное без изменений», «остальной код без изменений», «без изменений ниже», «rest of the file», «rest unchanged», «code unchanged», «existing code».
Под каждой частью: «Самопроверка unpack: ✅ — проверил строки по (1) и фразы по (2)».
Отказ только из-за фразы в словах (не строка-заглушка в коде) и Автор сказал ШТАБу «п.2 — да» — Автор правит сам: code .tmp/bundle.txt → Ctrl+G номер строки → фразу заменить на «как есть» → Ctrl+S → unpack заново.
Исключение: пакет отклонён ТОЛЬКО из-за цитаты этих фраз в docs/process/*.md — раскладка командой python3 tools/unpack.py --allow-placeholder .tmp/bundle.txt, написать это в ИТОГЕ. Для других файлов флаг запрещён.

## 4. Памятка размер
Лимиты: docs/STATE.md ≤ 20 480 Б; docs/DEFECTS-FOUND.md < 25 000 Б; docs/decisions/DECISIONS.md ≤ 8 192 Б; другие — по карточке или старту.
До выдачи оценить байты (кириллица 2 Б), цель ≤ 85 % лимита (15 360 → ≤ 13 000). Не влезает — резать ДО выдачи.
Под частью: «Самопроверка размера: кириллица ≈K зн × 2 + прочее ≈P + спецзнаки ≈S = ≈N Б из L». Знак ✅ без формулы запрещён; не посчитал — «не посчитано»; файлов с лимитом нет — «лимитов нет».

## 5. Шаги Codespaces — в ответе с последней частью пакета
Только шаги ниже, каждый одной строкой. Без «что увидишь», «если не так», объяснений команд, чек-листа в конце и пересказа карточки или PR.
В блоках только команды, без комментариев; gh не использовать. Ветку, цели и текст коммита взять из карточки или старта.
Строка wc -c — только если в пакете есть файл с лимитом; строка chmod +x — только если есть новый файл *.sh. Пакет только из docs — bash tools/check.sh без целей.
Шаг 1. Ты, в терминале Codespaces course-bot: создай ветку
    cd /workspaces/course-bot
    git checkout main && git pull
    git checkout -b <ветка>
    mkdir -p .tmp && code .tmp/bundle.txt
Шаг 2. Ты, в bundle.txt: вставь части 1–N подряд и сохрани (Ctrl+S)
Шаг 3. Ты, в терминале: разложи пакет и проверь
    python3 tools/unpack.py .tmp/bundle.txt
    wc -c <файлы с лимитом>
    chmod +x <новый файл *.sh>
    bash tools/check.sh <цели>
    git add -A && git status
Шаг 4. Ты, в терминале: коммит и отправка — только если unpack «ГОТОВО», check зелёный и в git status ожидаемые файлы; иначе вывод неси в это окно
    git commit -m "<текст коммита>"
    git push -u origin <ветка>
Шаг 5. Ты, на сайте GitHub: открой PR по ссылке из терминала, вставь заголовок и описание, не мержи
Заголовок PR и описание PR (по AGENT-BRIEF.md, раздел 10) — двумя отдельными код-блоками. Сразу под ними — ИТОГ ДЛЯ ШТАБА (раздел 6).
Исправление (З2, З3): причина одной строкой; пакет только с изменёнными файлами, каждый целиком, по правилам раздела 2 со своим планом частей; шаг 1 — одна команда code .tmp/bundle.txt (заменить всё содержимое, Ctrl+S); коммит «fix: <что>»; ИТОГ заново.
Репо DOCS-course-bot: те же шаги, но cd /workspaces/DOCS-course-bot и bash tools/checks.sh без целей.
Терминал: без heredoc; один блок команд — до 10 строк; файлы — только через редактор или пакет.

## 6. ИТОГ ДЛЯ ШТАБА — сразу под описанием PR, одним код-блоком
Заменяет прежние блоки ИТОГ и ПЕРЕДАЧА окна. Пишется до запуска команд: только то, что сделано в пакете. Номер PR и CI не ждать и не просить; «check ✅» и «CI ✅» не писать.
    ИТОГ ДЛЯ ШТАБА
    Задача: <id> · Ветка: <имя> · З<1/2/3>
    Файлы: <пути, как в пакете>
    Состояние: <пакет полный / не закончено: что осталось>
    Отличия от карточки или старта: <или «нет»>
    Сверх задания: <что пришлось сделать без указания ШТАБа и почему, или «нет»>
    Ручная правка .github/**: <какая или «нет»>
    Тесты: <что добавлено или изменено; что идёт только в CI>
    РЕВЬЮЕР: <да/нет — раздел 14 карточки>
    Сервер: <что проверить или «выкат позже (PLAN §4)»>
    Ответы ШТАБу: <на вопросы из старта, или «нет»>
    Вопросы Автору: <только по К-4, или «нет»>
    Дальше: <один шаг Автора>
ПРОЕКТИРОВЩИК и ИССЛЕДОВАНИЕ добавляют в этот блок поля своей ПЕРЕДАЧИ из DESIGNER.md, которых здесь нет.
В ответах без последней части (части пакета, «Далее», вопросы) вместо блока — одна строка: «ПЕРЕДАЧА: <задача> · <ветка> · выдано частей k из N · дальше: <шаг>».
Не уложились в бюджет или окно сжалось — ИТОГ со строкой «Состояние: не закончено», Автор открывает новое окно и вставляет его в старт.
