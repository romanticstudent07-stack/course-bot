# СЕРВЕРНЫЙ — интерфейс ШТАБ ↔ серверный чат (IRONCLAD)

Серверный чат у Автора ОДИН, постоянный, со своим промптом (хранится у Автора, в репо
его нет — репо публичный). Этот файл нужен ШТАБу: как писать задания и что ждать назад.
Новое окно серверного чата — только если его история сжалась; открывает его Автор
со своим промптом.

## Факты сервера (для составления заданий)
- Домашний ноутбук, Ubuntu 26.04, 8 ГБ RAM, HDD (сборка медленная). Все порты — 127.0.0.1.
- Репо: ~/course-bot. Сервер работает ТОЛЬКО с main (git checkout веток запрещён).
- Compose — только так:
      cd ~/course-bot && docker compose --env-file .env -f infra/docker-compose.dev.yml <команда>
- Применить .env — up -d (не restart). Пересобрать один сервис — up -d --build --no-deps <сервис>.
- Норма: 7/7 Up, 5 healthy (healthcheck нет у bot и projector; у redis — redis-cli ping с infra-melochi);
  одноразового migrate в ps нет — это норма. WARN «Bake / buildx» — не ошибка.
- Чужие контейнеры maxmover и tg_vk — не трогать. cloudflared на сервере — чужой.
  Funnel 8443 в tailscale serve status — maxmover.
- Запрещено: docker system prune, удаление volumes, правка чужого, вывод .env и секретов.
- Перед миграцией БД — бэкап pg_dump -Fc в ~/backups-coursebot/ (автобэкап — 03:30 MSK).
- Миграции и загрузка текстов — только одноразовый сервис migrate: build migrate → run --rm migrate
  (infra/SERVER-IRONCLAD.md, «Миграции и тексты (B-3d)»). У api пароля владельца БД нет (B-3d).
- Сравнивать с прошлым hash main (git diff --stat <старый hash> HEAD), а не с HEAD~1.

## Задание от ШТАБа (Автор вставляет в серверный чат целиком)
    ЗАДАНИЕ ДЛЯ СЕРВЕРНОГО ЧАТА — задача <id>, PR #<N> (после мержа)
    Было: main = <старый hash>
    Цель: <одна строка>
    Команды: <по группам, с ожидаемым результатом каждой>
    Развилки: <если видишь X → делай Y>
    Не делать: <перезапуск контейнеров / миграции и т.п., если не нужно>
    Отчёт: блоком ОТЧЁТ СЕРВЕРА (формат ниже)
ШТАБ пишет задание без <плейсхолдеров>: все hash, имена и команды — уже подставлены.

## Обязательные пункты задания (решение Автора 26.10)
- «Вне окна сервера с прошлого отчёта»: все ручные проверки Автора с прошлого ОТЧЁТА СЕРВЕРА — аккаунт (метка А1–А4), где (личка бота / тема «Доступ» / Mini App), что сделал, что изменилось в БД — или «нет».
- Ожидаемые числа в задании = последний ОТЧЁТ СЕРВЕРА + эти действия; не из сводок и не из памяти.
- «После задания»: какие проверки Автор делает сам, каким аккаунтом (метка), в каком порядке с командами сервера — или «нет».
- Нет этих пунктов → Автор задание не несёт и пишет ШТАБу «Нет пункта Вне окна».
- Аккаунты в репо — только метками А1–А4 (имена знают только Автор и ШТАБ). Логи — только с --since/--until и tail.

## Отчёт назад в ШТАБ (до 20 строк)
Принимается блок «ОТЧЁТ СЕРВЕРА» или «ДЛЯ АГЕНТСКОГО ЧАТА» — это одно и то же.
    ОТЧЁТ СЕРВЕРА — задача <id>, PR #<N>
    main: <старый hash> → <новый hash>
    diff --stat: <файлы>
    Проверки: <каждая — ✅/❌ и короткий вывод>
    Контейнеры: <Up/healthy>
    Замечания: <или «нет»>
Автор несёт этот блок в ШТАБ и сохраняет в раздел 3 своего SHTAB-CONTEXT-CHAT.txt.
