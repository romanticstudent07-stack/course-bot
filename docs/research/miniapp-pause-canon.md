## Запись и восстановление — проект К-5

Один незавершённый слот на владельца. В таблице «слот» означает до подтверждения/окончательного отказа или согласованной остановки; календарный срок не утверждён. Строки слота удалять транзакционно; каждый такой атрибут также удаляется при полной очистке. Таблица — проект представления разрешённых метаданных, не утверждение конкретных полей и не признание их нечувствительными.

| Поле | Назначение и связь с участником | Срок / удаление |
|---|---|---|
| `v` | Версия декодера, связь через слот | Слот |
| `kind` | Выбор POST, раскрывает вид действия | Слот |
| `opId` | UUID повтора, связывается с серверной записью | Слот |
| `days` | Неизменная длительность request | Слот |
| `expectedStart` | Дата намерения request, если выбран этот механизм Q1 | Слот |
| `pauseId` | Неизменная цель cancel/resume, ссылка на паузу | Слот |
| `tgOwnerTag` | Локальная привязка к Telegram ID; даже хеш — не анонимизация и не авторизация | До смены владельца / полной очистки; проверять и при пустом слоте |

Не хранить снимок участника или паузы (`snapshot_ttl: 24h` к очереди не относится), PID в открытом виде, initData, hash подписи, токены, содержимое ответов. Поля без функции не добавлять; `server_now` не сохранять.

1. На входе и перед POST сверить тег по актуальной raw initData через `tgUserIdFromInitData` только для локального владения; R380 также указывает mismatch `Telegram.WebApp.initDataUnsafe.user.id` на загрузке. Нет ID или источники расходятся — не отправлять. Сервер доверяет лишь проверенной initData. При смене сразу остановить старый worker, очистить таймеры, отменить локальный fetch где возможно, игнорировать поздние ответы, остановить другие вкладки. Полная очистка всех IDB приложения перед запуском нового владельца; при блокировке удаления отправка закрыта. Отмена fetch не откатывает сервер. Охват и механика wipe требуют инвентаризации.
2. Под общим межвкладочным lock: прочитать слот → `queued` → дождаться commit → зафиксировать `uncertain` перед fetch. Ошибка IDB до commit — ноль POST, видимая ошибка, без memory fallback. Кандидат — Web Locks от чтения до фиксации ответа; без безопасного lock не отправлять. После падения вкладки ещё может работать старый серверный вызов: его защищает серверная идемпотентность, не lock браузера.
3. Сеть/таймаут/5xx или неполный успех → прежний `uncertain`; offline — ждать online/возврата. Backoff на op-id, ориентир 2 с × 2^n, потолок 60 с; сохранить расписание, брать максимум с Retry-After и имеющимся сроком ожидания. 429 не стирает прежнюю неопределённость. Ошибка записи после POST → остановка, при восстановлении только прежняя записанная попытка. 401/403 — ждать действительной авторизации того же владельца; 404/422 — остановка без автоцикла, не доказательство исхода первого вызова.
4. 201/202 → закрыть запись после надёжной фиксации, перечитать GET; 202 не означает применения. Открытый GET не доказывает принадлежность попытке, GET=null не доказывает, что её не было. Повторить тот же op-id, только если контракт позволяет безопасно получить результат или применить исходную операцию. При доказанном бизнес-отказе закрыть запись, показать сообщение и перечитать; черновики не удалять. При неизвестном исходе остановить и сообщить, новый UUID — только после отдельного явного действия. Доказанная коллизия: аудит безопасности, блокировка отправки, флаг, текст R339 и wipe на следующем открытии. Неизвестный 409 не записывать как доказанную коллизию.
5. Закрытие останавливает worker и очищает RAM насколько позволяет среда. При входе сначала владелец/флаг/проверка актуальности, затем восстановление. При недопустимой исходной дате не применять операцию впервые и предложить новое подтверждение; уже применённая возвращает прежний результат. Не обещать физическую очистку на закрытом устройстве.

## #267: четыре обязательные регрессии

1. Сеть → 429 → истечение Retry-After → те же days/UUID; проверить и после пересоздания worker.
2. `start_at <= now`: один старт серии на `(pause.id,start_at)`, не перезапускать из apply. Тесты: прошлое, равенство, задержка перехода, 1+5 GET через 2 с, очистка.
3. ETA/start не вытесняют серию после cancel/resume через `readSeq`; один координатор чтений, финал очищает busy/polling только своей серии. Тесты с отложенными ответами resume/ETA и cancel/start в обоих порядках и после ухода. GET-повторы не POST-backoff.
4. `checkDayAccess` сохраняет Retry-After; `DayGuard` и кнопка ошибки /paused реально disabled, обработчик тоже закрыт до срока, потом один ручной GET. День не открывается из ошибки, active или таймера; «Помощь» и онбординг сохранить.
