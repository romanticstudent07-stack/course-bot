## Р-13 / B5 (Issue #15) — РЕШЕНО Автором 19.10.2026, вариант Б:
full_backup_rotation_cycle = 30 дней (полные бэкапы PostgreSQL с учётом WAL).
Закрывает одним числом: boot-gate п.6 (ADD5: без числа прод запрещён),
срок хранения erasure_blacklist (RET-2: не меньше «ротация + WAL», т.е.
≥ 30 дней + WAL) и дефект D-12 (appendix/D-source-defects.md канона) (TTL чёрного списка ссылался на незаданное число).
Факты о бэкапах Timeweb DBaaS (официальная документация docs/dbaas/dbaas-manage/
backup, проверено 19.10): физические бэкапы — ручные и по расписанию; в расписании
настраиваются «периодичность (ежедневно, еженедельно, ежемесячно), количество
копий и дата начала»; восстановление — «в состоянии на момент создания копии»;
физический бэкап скачивается файлом .qcow2 (для PG/MySQL кластеров, созданных
после 01.01.2025). Про PITR в документации Timeweb записей нет.
Копии бэкапов вне ноутбука — Timeweb Object Storage (Р-10).
Правки для ШТАБа: Issue #15 закрыть решением «30 дней»; подставить число вместо
full_backup_rotation_cycle во всех местах (boot-gate п.6, RET-2, D-18 (appendix));
правовая достаточность срока — юристу (ADD5 Legal-STUB S4, пункт C1 Захода 3);
фразу «152-ФЗ рекомендует ≥ срока хранения PII» из Issue #15 НЕ наследовать —
нормы с такой рекомендацией не найдено.
