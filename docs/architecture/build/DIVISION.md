# Разделение реализации: Mini App / Bot / Backend

Три «уровня» реализации — каждый берёт свою часть каждого архитектурного блока. При расхождении с корпусом побеждает корпус; этот файл — карта распределения ответственности.

## Принцип разделения

**Mini App** (клиент, `apps/miniapp/`):
- Все пользовательские экраны (онбординг, дневной модуль, Чек-Ап, Карточка, «Мои согласия», просмотр Карты изменений, оплата, отзыв согласий, экспорт данных).
- Первый запуск = точка создания `pid` (SEAM-PATCH-1).
- Работа с фото 4-х сторон, отправка отчётов, рефлексий.
- CSP `default-src 'self'` + белый список (E2 ERRATA).

**Bot** (Telegram-бот, `apps/bot/`):
- Меню-кнопка → открытие Mini App (`WebAppInfo`, `/setmenubutton`).
- Три-тир уведомления (P-5): системные / напоминания / мотивационные.
- Admin-команды из whitelist (35 команд Б17). **Ровно этот набор — и ничего сверх.**
- Reply-команды в Рабочей группе (`/revert`, `/approve`, `/refund`, `/life`, `/pause_grant`, `/audit`, `/legal`, `/graph`, `/announce`, `/panic_maintenance`).
- Callback-кнопки под сообщениями Бота (командные кнопки Карточки из Б17).
- Whitelist admin-ID + hard-confirm (E3 ERRATA).
- Доставка результата экспорта данных (файл в чат) и уведомлений о завершении стирания.

**Backend** (общий сервер, `apps/api/`):
- OpenAPI-сервер Mini App (`/miniapp/v1/...`).
- Обработчик Telegram Webhook (входящие апдейты для бота).
- Все саги (Refund, Photo Ingest, Red Zone, Erasure).
- `participant_state_projector`, `outbox`, `DLQ`, `export-worker`.
- Единый источник `text_registry`, `role_capability_matrix`, `hard_confirm_phrases`, `topic_bindings`.

## Что реализуется в Mini App **приоритетно** (MVP-минимум)

Порядок первых итераций (первые 4–6 недель):

1. **Онбординг + Mini App skeleton** — SEAM-1, возрастной гейт, создание `pid`, оплата первого этапа (Блок 4).
2. **Экран дня + отправка отчёта + жизни** (Блоки 2, 3).
3. **Чек-Ап + Карточка участника (сторона Участника)** (Блоки 5, 6).
4. **Клиент Mini App v3.4** — IndexedDB, идемпотентность, CSP (Блок 14).
5. **Refund Saga через Mini App** (Блок 16).

## Что реализуется в боте **приоритетно**

1. **Menu Button → Mini App URL** (`/setmenubutton` в BotFather).
2. **Whitelist admin-ID + hard-confirm** — Б17, 35 команд.
3. **Reply-команды в Рабочей группе** — `/revert`, `/approve`, `/refund`, `/life`, `/pause_grant`.
4. **Три-тир push** — уведомления через Bot API.
5. **Fallback-заглушка** для участников, открывших бота без Mini App: «Установите последнюю версию Telegram и откройте кнопку меню».

## Что НЕ переносим в Mini App (осознанное решение)

- **Панель Автора (Блок 17)** остаётся в боте. Причина: 35 admin-команд + hard-confirm + двухшаг + reply-parameters — это интерфейс, где Mini App даёт больше рисков (сложнее аудит), чем ценности. Владелец и так живёт в Рабочей группе.
- **Массовая рассылка `/announce` и broadcast-инспектор** — только в боте (Bot API проще; в Mini App были бы дубли).
- **`/panic_maintenance`** — только в боте (должен работать даже при полностью упавшем Mini App).

## Как этот файл читать агенту

При задаче «реализуй блок N» — открывай этот файл первым, находи строку блока и распределяй код по трём подкаталогам:

```
apps/miniapp/   ← фронт Mini App (React + Vite + @telegram-apps/sdk-react)
apps/bot/       ← Telegram-бот (Python + aiogram / grammY)
apps/api/       ← backend (FastAPI + PostgreSQL + Redis)
```

Если задача пришла без указания блока — открой [../../CONTEXT.md](../../CONTEXT.md), потом [../../AGENTS.md](../../AGENTS.md), потом этот файл.
