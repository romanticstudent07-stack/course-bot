# [АРТЕФАКТ ДОЛГА · подшить под → БЛОК 10 · узел D2 · CLOSE · v3.2]

осн. адресат Б10 (два транспорта); адресаты-содержимое: Б13 («Пройденное»), Б10-Ш2 + Б4/Б6 (согласия/удаление); STUB-хвост → Б9 (тексты раздела)

## Выжимка

D2 закрывает два разных транспорта Б10 с разными адресатами содержимого. (а) «📖 Пройденное» — транспорт Б10 (точка НАБОРа Ш5 + edit-in-place доставка `proydennoe_tree` Р86, `b13_quota_charge`) → содержимое Б13 (дерево D1). (б) «Мои согласия (вкл. удаление ПДн)» — одна объединённая кнопка НАБОРа (Ш7, инвентарь 5 точек) → раздел Б10-Ш5 (Слой 2 inline) с двумя под-входами: просмотр согласий (Б4-4.10/Б6 `command_legal_data`) + инициация удаления (Б10-Ш2 `erasure_request`: active→pending_erasure, `cooling_off`). Поправка адресации: инициация ≠ исполнение — кнопка двигает фазу Б10-Ш2, НЕ дёргает A1; A1 (`guarded_transition`) добивает CAS-переход в `erased` по таймеру `cooling_off`; A4 — обезличивание. Б13 к удалению непричастен (удаление ≠ пройденный контент); единственное касание — следствие erasure: `erased` → `progress_readonly: hidden` (Ш4), Б13-Ш6 «Пройденное недоступно».

## Ключевые решения

Р-D2.1 — два транспорта, разные адресаты; D2 = только транспорт Б10, содержимое наследуется. Р-D2.2 — «удаление ПДн» не отдельная кнопка, а под-вход объединённой «Мои согласия» (Ш7); развилка внутри раздела — Слой 2 Б10-Ш5. Р-D2.3 (поправка) — цепочка удаления: Б10-транспорт → Б10-Ш2 (`erasure_request`, фазовая машина, `cooling_off`) → A1/A4 (Б15 исполнение). A1 не принимает пользовательский вход. Р-D2.4 — согласия: транспорт Б10, содержимое Б4/Б6 (`command_legal_data`, immutable consent log).
