# ПРИЛОЖЕНИЕ B. СВОДНЫЙ РЕЕСТР FAIL-SAFE

Обязательная секция каждого блока. Сводка накопленных защит:

**Необратимые действия** — только через двухшаговое подтверждение. Кнопка «Да» ставится не на месте первой кнопки (защита от двойного случайного тапа). Обратимые/переключаемые — в 1 тап. Касается: `revert`, зачисление оплаты, рефанд, пауза (у Автора), пауза (у Участника — «Поставить на паузу? [Да][Нет]»), блокировка/разблокировка, ручные операции с жизнями. _(Из перечня удалён `place` — поправка v3.1.)_

**Whitelist admin-ID.** Команды Боту принимаются только от лиц в whitelist (Автор + партнёр; задел на роли для будущих сотрудников). Команда от не-в-whitelist → игнор + лог.

**Команда без reply** (Бот не знает, о ком речь) → Бот не выполняет, просит reply.

**Валидация значений команд.** Несуществующий день/модуль (`/revert 2.99`, `/revert 5.1` при 4 модулях) → не выполняется, Бот сообщает границы. Нельзя превысить максимум 3 жизни / уйти в минус. _(Из примеров удалён `/place` — поправка v3.1.)_

**Атомарность операций с жизнями** (транзакция/блокировка) — защита от гонки «списание Ботом vs возврат Автором».

**Гонка «сдача vs дедлайн»** — по серверному времени.

**Двойное нажатие** — идемпотентность кнопок.

**Смена ТЗ** — только со следующего дня, не задним числом.

**Redis durability** — критичные события пишутся в PostgreSQL синхронно, буфер только для аналитики.

**Пауза как щит** — заблокирована правилом «пауза не спасает горящий дедлайн».

**FSM-состояние персистентно.**

**Зачёт дня** — только по подтверждённой записи в БД (П-31), без ложного успеха; при сбое — ошибка и повтор.

**Авто-прохода нет** — решение по рефлексии всегда за Автором; недоступность Автора решается тайной паузой.

**Эффект очереди** — отдельная отложенная задача, не влияет на зачёт дня / жизнь.

**Callback привязан к participant_id** — действие под сообщением X адресует именно X.

**Бот-администратор с can_delete_messages** — проверяется при старте, иначе автоочистка/замена не работают.

**Аудит-лог доступа к карточкам (152-ФЗ):** кто, когда, чью карточку смотрел.

**Курс не запускается без заполненных юр.текстов.**

**Неприкосновенность первой записи журнала замеров** и всех append-only логов (замеры, рефлексии, деньги).

**Идемпотентность денежных операций** — двойной возврат/зачисление невозможен.

**Нет пустых экранов** ни в одном состоянии (П-21).

Правило: при разборе КАЖДОГО следующего блока отдельно прорабатывается секция «🛡 Fail-safe».

## YAML — сквозные правила (Приложения)

Единый YAML приложений, перенесён с учётом поправки v3.1: ключ `P6_place_command` удалён из `patch_1_global`; упоминания `place` в `failsafe_registry` удалены (сами правила валидации и двухшагового подтверждения сохранены — исчезло только упоминание `place` как их примера). Тот же блок продублирован в [A-patch1-global-rules.md](A-patch1-global-rules.md) — оба приложения самодостаточны; при правках YAML синхронизировать обе копии.

```yaml
# ============================================================
# ПРИЛОЖЕНИЯ — сквозные правила (Патч-1) + Fail-safe реестр
# Версия: consolidated v3 + поправка v3.1
# ============================================================

patch_1_global:
  P1_module_numbering: global_sequential      # сквозная нумерация модулей
  P2_author_tz: config_defined                # ТЗ Автора (сводки/график); прочее — ТЗ участника
  P3_night_mode: CANCELLED                     # отменён (Ф-25 / Н-2), бот учитывает ТЗ участника
  P4_return_counter: tracked_soft_limit        # счётчик возвратов, лимит не жёсткий
  P5_notifications_3tier:
    system: non_disablable                     # пауза, жизни, оплата, блокировки
    reminders: adjustable                      # лестница, дедлайны
    motivational: disablable                   # полуденная неактивность
    settings_screen: checkboxes                # детали — Блок 9
  # P6_place_command — УДАЛЁН поправкой v3.1

failsafe_registry:
  irreversible_actions: two_step_confirm       # "Да" не на месте первой кнопки
  reversible_actions: one_tap
  whitelist_only: true
  non_whitelist: [ignore, log]
  command_without_reply: [refuse, ask_reply]
  value_validation: [existing_day_module, life_bounds_0_3]
  life_ops_atomic: true
  race_by_server_time: true
  buttons_idempotent: true
  tz_change: next_day_only
  critical_writes: synchronous_postgres
  pause_not_saving_burning_deadline: true
  fsm_persistent: true
  day_counting: on_confirmed_db_write          # П-31, без ложного успеха
  auto_pass: NEVER
  queue_effect_isolated: true                  # не влияет на зачёт/жизнь
  callback_bound_to: participant_id
  bot_admin_can_delete: required_on_start
  card_access_audit_log: true                  # 152-ФЗ
  no_course_without_legal_texts: true
  append_only_logs: [measurements, reflections, money]
  money_ops_idempotent: true
  no_empty_screens: true                       # П-21
```
