# CANONICAL-SOURCES.md — каноническая модель источников

Этот файл — арбитр. Он отвечает на два вопроса:

1. **Какой файл считается источником истины**, если один и тот же Блок
   представлен и верхним файлом `NN-….md`, и подпапкой `NN/`.
2. **Как читать YAML в патчах**, где значения уже отменены ERRATA.

## Зачем этот файл существует

После нарезки крупных Блоков в каталоге `architecture/` сосуществуют:

- верхние файлы общего ряда (`10-lifecycle-return.md`, `15-content-antipiracy.md`,
  `17-author-panel.md`, `99-legal.md`);
- подпапки с частями (`10/`, `15/`, `17/`, `99/`).

Плюс в патчах И1/И2/И4/Б17 YAML-блоки содержат исторические снимки
значений, которые уже отменены ERRATA. Без явных правил и то, и другое
опасно для агента.

## Каноническая модель крупных Блоков

| Блок | Верхний файл | Подпапка | Роль верхнего файла | Роль подпапки | Победитель при расхождении |
|---|---|---|---|---|---|
| 10 | `10-lifecycle-return.md` | `10/` | вводная + оглавление частей | посекционный носитель содержания | файлы из `10/` |
| 15 | `15-content-antipiracy.md` | `15/` | единая сборка (обзор) блока | посекционный носитель содержания | файлы из `15/` |
| 17 | `17-author-panel.md` | `17/` | вводная + оглавление частей | посекционный носитель содержания; YAML-контракт `block_17` в `17-99-yaml-full.md` | файлы из `17/` |
| 99 | `99-legal.md` | `99/` | вводная + навигация | посекционный носитель содержания; среди частей 99 старшая — `99-03-yaml-v2ext.md` (правило самого блока) | файлы из `99/` |

## Правило чтения для агента

Если задача касается Блока 10, 15, 17 или 99:

1. Открыть верхний файл (получить контекст и оглавление).
2. Открыть нужную часть из подпапки `NN/`.
3. Работать по содержанию из подпапки.
4. Если верхний файл говорит одно, а часть — другое, приоритет у части.

Если задача касается патчей И1/И2/И3/И4/Б17:

1. Открыть целевой патч.
2. **Обязательно** открыть [normative/OVERRIDES.yaml](normative/OVERRIDES.yaml)
   и держать в контексте.
3. При парсинге YAML в патче применять `OVERRIDES.yaml`: если поле есть
   в OVERRIDES с совпадающим `path` — взять оттуда, не из патча.
4. Прочитать [normative/README.md](normative/README.md), «Открытые
   несовместимости» — список из 5 пунктов; при попадании в один из них
   действовать по указанному fallback'у.

Нормативный стек (`I1…I4`, `B17`, `SEAM-PATCH-1`, `ERRATA-UNIFIED`) — над
всеми верхними файлами и над всеми подпапками. Порядок старшинства —
[normative/README.md](normative/README.md).

## Эталон для сверки YAML block_17

YAML-контракт `block_17` в `17/17-99-yaml-full.md` **не** является полной
копией `17-author-panel.md` (после нарезки в индексе YAML больше нет).
Эталон для сверки:

1. **Первичный эталон** — раздел «ЕДИНЫЙ YAML-КОНТРАКТ БЛОКА 17» в
   оригинальной `Архитектура.docx` (владеет Автор).
2. **Вторичный эталон** — версия `architecture/17-author-panel.md` из
   git-истории до нарезки (коммит `84d357bcf7…`, строки 293–761):

   ```bash
   git show 84d357bcf7a432963bfea88ea43e8590821fd533:architecture/17-author-panel.md
   ```

3. **Реестр синтаксических нормализаций** —
   [appendix/E-yaml-normalizations.md](appendix/E-yaml-normalizations.md).
   Любая правка YAML `block_17`, отклоняющаяся от эталона, должна быть
   внесена туда отдельной записью `N-NN`.
4. **Реестр ERRATA-переопределений** —
   [normative/OVERRIDES.yaml](normative/OVERRIDES.yaml). Отменённые
   значения из патчей И1/И2/И4/Б17 переопределяются здесь.

Правило: **байт-в-байт равенство с эталоном + список нормализаций +
применение OVERRIDES при чтении**, а не буквальное байт-в-байт без
исключений.

## Что считается нарушением этой модели

1. Верхний файл крупного Блока (10/15/17/99) содержит норму, которой нет
   ни в одной части, и не помечен явно как «единая сборка» или «вводная».
2. Агент ссылается на `_WIP-architecture-split.md` как на источник
   истины (это исторический служебный журнал; действующий реестр
   дефектов — `appendix/D-source-defects.md`).
3. Файл `17/17-99-yaml-full.md` изменён относительно эталона без записи
   в `appendix/E-yaml-normalizations.md`.
4. Агент реализовал что-либо, парся YAML в И1/И2/И4/Б17 напрямую, **не
   применив** `normative/OVERRIDES.yaml`.
5. Появилось новое ERRATA-переопределение, не добавленное в OVERRIDES.

## Правило нулевых содержательных потерь

Любая новая нарезка/пересборка допустима только если выполнены все пункты:

1. Все заголовки исходного файла перенесены (grep по `^#` до и после).
2. Все таблицы перенесены (сравнение количества строк матриц).
3. Все YAML-блоки перенесены целиком (сравнение размера ± зарегистрированные нормализации).
4. Все относительные ссылки перепроверены.
5. Верхний файл после нарезки не содержит норм, которых нет в частях.
6. Контроль `bash tools/checks.sh` проходит зелёным.
7. Каждое отступление зарегистрировано в
   [appendix/E-yaml-normalizations.md](appendix/E-yaml-normalizations.md) или в
   [normative/OVERRIDES.yaml](normative/OVERRIDES.yaml).
