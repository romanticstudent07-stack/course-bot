# БЛОК 6. КАРТОЧКА УЧАСТНИКА

> **Переопределено патчем Б17 и уточнено ERRATA-UNIFIED.** Командные кнопки, видимость секций по роли и состоянию, три полосы паузы — [normative/B17-admin-panel-patch.md](normative/B17-admin-panel-patch.md). Правила видимости для роли `moderator` требуют решения Автора (роль не определена). Входящий долг из Б10 (проекция состояния в карточный `status`) не закрыт. Носитель текстов кнопок — `text_registry` (И4). Фразовый hard-confirm сохранён (E3 ERRATA). См. [normative/I4-wave-d.md](normative/I4-wave-d.md), [normative/errata-unified.md](normative/errata-unified.md).

## 6.1. Принцип

Единый источник правды — БД. Карточка формируется свежей из БД в момент запроса (не хранится готовой). Доработанный Вариант 2.

## 6.2. Способы вызова

- По reply + /card (параметр не нужен, user_id из reply).
- По кнопке 📇 Карточка под алертами/сообщениями (один тап, привязка автоматическая).
- По параметру /card #000123 или /card @username (когда нет reply/кнопки).

## 6.3. Короткий номер участника

Каждому Участнику присваивается короткий человекочитаемый номер (#000123) при регистрации; показывается во всех служебных сообщениях рядом с именем.

## 6.4. Содержимое карточки (порядок)

- **Кто:** ФИО, возраст, откуда (регион), часовой пояс, кликабельная ссылка tg://user?id=, @username, телефон, короткий №.
- **Было → стало:** вес (старт → текущий), Чек-Ап-зона (старт → последняя, с пометкой улучшение/ухудшение). В карточке показывается стартовый показатель, с которым Участник зашёл, + текущий.
- Кнопка 📊 Полная Карта изменений.
- **Текущая позиция:** Этап, модуль.день, статус (активен / пауза / блок / ждёт оплаты / спящий / архив).
- **Жизни:** осталось + журнал списаний.
- **Оплаты:** оплаченные Этапы, даты.
- **Паузы:** использована ли на Этапе, история.
- Счётчик возвратов на закрепление.
- Дата регистрации.

(Согласия / юр.данные в карточку НЕ входят — отдельная команда ⚖️ Юр.данные.)

## 6.5. Устаревание и чистота (Q-109)

Карточка всегда свежая из БД. В теме «Карточки» — не более одной карточки на участника (повторный запрос обновляет/заменяет). Автоудаление через 24 часа после последнего запроса.

## 6.6. Командные кнопки под карточкой (и под релевантными сообщениями)

Кнопки-ярлыки существующих команд (Блок 17). Нажатие не выполняет действие сразу, а запускает диалог параметров + подтверждение. Привязка к участнику автоматическая (reply не нужен).

Полный набор действий:

- **Прогресс:** ↩ Revert.
- **Жизни:** ❤️ +Жизнь, 💔 −Жизнь.
- **Пауза:** ⏸ Дать паузу, ▶️ Снять паузу, ➕ Доп.пауза.
- **Рефлексия** (в теме «Рефлексии»): ✅ Approve (Одобрить проход), ↩ Вернуть на закрепление (/revert).
- **Оплата** (в теме «Оплаты»): ✅ Подтвердить оплату, ✖ Отклонить оплату.
- **Блокировка:** 🔓 Разблокировать, 🔒 Заблокировать.
- **Рефанд:** ↩️ Оформить возврат (/refund) — под подтверждённым чеком и в карточке.
- **Информационные** (без подтверждения, только чтение): 📇 Карточка, 📊 Полная Карта изменений, ⚖️ Юр.данные.
- **Связь:** ✉️ Написать участнику через Бота — Автор пишет текст в группе → Бот доставляет Участнику от имени Бота (не выходя из рабочего контекста).

## 6.7. Принцип размещения кнопок

Показываются только релевантные кнопки в контексте: под рефлексией — approve / вернуть + карточка + написать; под оплатой — подтвердить / отклонить + карточка (+ рефанд под подтверждённым чеком); под карточкой — полный набор. Не вешать всё везде.

## 🛡 Блок 6 — Fail-safe

/card — только whitelist. Без reply/параметра → просьба уточнить идентификатор. Несуществующий идентификатор → «не найден». Карточка = ПДн + данные о здоровье → только в теме «Карточки», только whitelist. Аудит-лог доступа обязателен (кто, когда, чью карточку смотрел) — 152-ФЗ. После действия командной кнопкой — карточка перерисовывается актуальной. Командные кнопки не выполняют действие сразу — запускают диалог параметров + подтверждение (защита от случайного тапа, необратимые действия двухшаговые). Карточка мигрированного не падает при отсутствии данных (показывает «нет данных»).

## YAML — карточка участника (Блок 6)

```yaml
# ============================================================
# БЛОК 6 — Карточка участника
# Версия: consolidated v3
# ============================================================

participant_card:
  source_of_truth: db
  generation: fresh_from_db_dynamic       # не хранится готовой (Вариант 2)
  location: topic_cards
  strategy:
    one_card_per_participant: true        # повторный запрос заменяет
    auto_delete_after: 24h

  short_number:
    format: "#000123"
    assigned_at: registration
    shown_with_name: everywhere

  invocation:
    - {mode: reply, command: /card}       # user_id из reply
    - {mode: button, label: "📇 Карточка"} # авто-привязка
    - {mode: parameter, examples: ["/card #000123", "/card @username"]}

  content_order:
    - who: [name, age, region, timezone, "tg://user?id=", username, phone, short_no]
    - then_now:
        weight: [start, current]
        checkup_zone: [start, latest, "+ пометка улучшение/ухудшение"]
    - button: "📊 Полная Карта изменений"
    - position: [stage, "module.day", status]   # active/pause/block/awaiting_pay/sleeping/archive
    - lives: [remaining, decrement_journal]
    - payments: [paid_stages, dates]
    - pauses: [used_on_stage, history]
    - return_counter: value
    - registration_date: value
  excluded_from_card: [consents, legal_data]     # -> команда ⚖️ Юр.данные

  action_buttons:
    behavior: safe_dialog_entrypoint + confirmation   # не выполняет сразу
    auto_bind_participant: true
    sets:
      progress: [revert]
      lives: [life_plus, life_minus]
      pause: [pause_grant, pause_lift, pause_extra]
      reflection: [approve_pass, revert]            # тема "Рефлексии"
      payment: [confirm_payment, reject_payment]    # тема "Оплаты"
      block: [unblock, block]
      refund: [refund]                              # под чеком + в карточке
      info_readonly: [card, full_change_map, legal_data]
      contact: [write_via_bot]
    placement: context_dependent                    # только релевантные (6.7)

  failsafe:
    access: whitelist_only
    no_identifier: ask_to_clarify
    unknown_identifier: "не найден"
    data_class: [pdn, health]                       # только тема cards, только whitelist
    access_audit_log: true                          # 152-ФЗ: кто/когда/чью
    after_action: redraw_card_fresh
    irreversible_actions: two_step_confirm
```
