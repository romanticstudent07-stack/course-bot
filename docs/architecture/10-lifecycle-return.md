# БЛОК 10. ЖИЗНЕННЫЙ ЦИКЛ УЧАСТНИКА И ВОЗВРАЩЕНИЕ ([СТАРТ])

> **Переопределено ERRATA-UNIFIED и SEAM-PATCH-1.** FSM участника — шесть состояний (И2, Р477 удалил `banned_soft`/`banned_hard`); `participant_state` — не источник, а проекция (E1: обычная таблица с проектором, единственный писатель — этот блок). Шаг 2 запуска [Старта] исполняется в first-launch Mini App (SEAM-1). Владелец `publish_epoch` — блок 14 (FIX1); блок 10 только дедуплицирует по паре `(stage_id, publish_epoch)`. Тела уведомлений — `text_registry` (И4). См. [normative/I2-wave-b.md](normative/I2-wave-b.md), [normative/I4-wave-d.md](normative/I4-wave-d.md), [normative/errata-unified.md](normative/errata-unified.md), [normative/seam-patch-1-onboarding.md](normative/seam-patch-1-onboarding.md).

Блок 10 — диспетчер состояний. Он не вычисляет контент и не считает деньги, а определяет, в какой фазе жизненного цикла находится участник, какие STATUS-признаки на него наложены, что ему в этом положении доступно и что происходит по кнопке [Старт]. Модель состояния действует в редакции Шага 1: одна эксклюзивная ось `lifecycle_phase` + набор status-флагов.

Блок объёмный и разбит по нумерованным шагам оригинала: один шаг = один файл в подпапке `10/`. Номер части соответствует номеру шага (Шаг 0 → `10-00-…`, Шаг 1 → `10-01-…`). Ссылаться следует на номер шага, тематические имена файлов — псевдонимы.
