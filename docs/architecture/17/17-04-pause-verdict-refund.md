# Блок 17 — Часть 04. Пауз-семантика, вердикт vs проход, refund-saga, цикл чек → reject → новый чек

> «Разделение вердикта и применения прохода», «Возврат оплаты как saga»,
> «Цикл чек → reject → новый чек».

## Пауз-семантика

Пауз-семантика фиксирована. `/pause_author` — административная (не тратит биржу пауз участника), обёртка `pause_shadow` в Б2. `/unpause_author` — снимает административную; `/unpause_user` — досрочно снимает пользовательскую. `/set_shadow`/`/unset_shadow` — переключатели теневого режима (мягко скрывают Автора). Контракты выхода из паузы владеет Б2; Б17 передаёт `reason_class` и `pause_id` для аудита.

## Разделение вердикта и применения прохода

Вердикт (`/approve`, `/revert`) и применение прохода Этапа — разные события. Автор ставит вердикт → Б7 меняет состояние рефлексии; проход Этапа применяется автоматом Б10 по правилам (все дни ОК/на границе), либо ручным `/complete_stage` в исключительных случаях. `/publish_stage` активирует «следующий Этап», `/withdraw_stage` — откатывает публикацию до фактического захода первого участника (по владельцу — Б14).

## Возврат оплаты как saga

`/refund` — сага: preflight → freeze выдачи → перевод (PSP) → обновление состояния/жизней → уведомления → close. Идемпотентность до `psp_transferred_at_utc`; после — только `/refund_rollback` (тоже сага). Все нештатные исходы — компенсирующие операции с явными записями в аудит.

## Цикл чек → reject → новый чек

Отклонение (`/reject`) фиксируется владельцем Б7; повторная отправка рефлексии — новый чек; Б17 не «залипает» на предыдущем разборе. Мастер `/revert` показывает трассу зависимости (что затронется) и требует явного согласия.
