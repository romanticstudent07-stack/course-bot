# Нормативный стек

Поверх корпуса `v3` действует стек нормативных патчей. Настоящий файл
описывает их старшинство и порядок присоединения.

## Две оси: порядок присоединения ≠ ступень старшинства

**Ось хронологии** (когда файл был подшит) и **ось старшинства** (кто
побеждает при конфликте) — **разные оси**. ERRATA-UNIFIED присоединена
раньше SEAM-PATCH-1, но у ERRATA более высокая ступень старшинства
(`highest_over_body_and_patches`), а у SEAM — `below_errata_unified`.

## Ось старшинства (сверху вниз, побеждает верхний)

```
корпус v3 → И1 → И2 → И3 → И4 → Б17 → SEAM-PATCH-1 → ERRATA-UNIFIED (высшая)
```

## ERRATA-переопределения как машиночитаемый слой

YAML в патчах И1/И2/И4/Б17 содержит **исторические снимки** значений,
которые уже отменены ERRATA. Прозаические врезки сверху патчей называют
правильные значения, но сам YAML остаётся старым — так требует оригинал
Архитектуры (`supersedes`-паттерн, стр. 407-420).

Чтобы агент, парсящий YAML напрямую, получил каноническое значение,
существует машиночитаемый реестр:

- [OVERRIDES.yaml](OVERRIDES.yaml) — список переопределений в виде
  `path → canonical_value` (E1, E2, E4, FIX1, N02, R477_TARGET и др.).
- [OVERRIDES.md](OVERRIDES.md) — человекочитаемый навигатор к нему.

Правило чтения обязательное: **прочитал YAML → применил OVERRIDES**.

## Открытые несовместимости (единый канонический список)

Ранее «три несовместимости» упоминались в двух местах с разными
пунктами. Ниже приведён **единый канонический список из пяти пунктов**
(пересечение + объединение). Все прочие упоминания в
[errata-unified.md](errata-unified.md), [../17-author-panel.md](../17-author-panel.md),
[I3-wave-c.md](I3-wave-c.md) — теперь ссылки на этот список.

### Список открытых несовместимостей (решение Автора)

| id | Несовместимость | Слои | Статус | Решение до Автора |
|---|---|---|---|---|
| **OPEN-1** | `/block` и `/unblock` — целевое состояние | Б17 vs Р477 (И2) | закрыто в OVERRIDES (R477_TARGET) | использовать `sleeping + author_pause(reason_class=block) + owner_review` |
| **OPEN-2** | видимость Карточки для роли `moderator` | Б17 | ждёт Автора | не разграничивать до решения; использовать `owner` |
| **OPEN-3** | `/erasure_finalize_before_cooling_off` vs 14-дневная отсрочка И3 | Б17 vs И3 | ждёт Автора | команда недоступна; действует более строгое требование И3 |
| **OPEN-4** | автоэскалация Red Zone за 60 сек | И3 vs NR-17.14 | закрыто в OVERRIDES (OPEN_C) | разрешена — эскалация в `sleeping`, не в `banned_*` |
| **OPEN-5** | роли `finance`/`moderator` не определены в глоссарии | Б17 vs глоссарий | ждёт Автора | использовать `owner`; не различать до решения |

**Итог:** из пяти — три закрыты через OVERRIDES/уточнения,
два (OPEN-2 и OPEN-5) реально ждут решения Автора. OPEN-3 фактически тоже
блокирует прод-запуск команды `/erasure_finalize_before_cooling_off`, но
не блокирует остальную реализацию.

## Другие открытые вопросы

- **`hard_ban` в контракте доставки И4.** Не вычеркнут явно после Р477
  (И2). Считать нейтрализованным через OVERRIDES.R477_TARGET.
- **Коллизия нумерации согласий `C5`.** В И1/И3 = фото-согласие, в
  юрблоке = трансграничная передача. См. `appendix/D-source-defects.md`,
  Д-10.

## Как читать патчи (краткая инструкция агенту)

1. Прочитать `AGENTS.md` → `CONTEXT.md` → [../CANONICAL-SOURCES.md](../CANONICAL-SOURCES.md).
2. Прочитать этот файл (нормативный стек + старшинство).
3. Прочитать [OVERRIDES.yaml](OVERRIDES.yaml) — держать в контексте на
   протяжении всей задачи.
4. Прочитать целевой патч (например, `I2-wave-b.md`).
5. При парсинге YAML в патче применять `OVERRIDES.yaml` (см. правило чтения выше).
6. При расхождении между слоями — правило верхнего.
