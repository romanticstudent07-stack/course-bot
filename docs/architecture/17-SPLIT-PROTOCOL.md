# 17-SPLIT-PROTOCOL.md — протокол безопасной нарезки Блока 17

## Текущий статус

Блок 17 **нарезан** по этому протоколу.

- Верхний файл `architecture/17-author-panel.md` — оставлен как **вводная + оглавление частей** (индекс).
- Содержательные части лежат в `architecture/17/` — один раздел = один файл.
- YAML-контракт `block_17` перенесён в `17-99-yaml-full.md` **дословно и побайтово**
  из исходника (строки 293–761), без сокращений и переформатирования.
- Каноническая модель источников — [CANONICAL-SOURCES.md](CANONICAL-SOURCES.md), строка Блок 17.

## Почему потребовался протокол

`17-author-panel.md` содержит в одном месте:

- назначение блока и границы;
- модель ролей (окончательная);
- каталог команд;
- UX-контракт входа, двухшаг, идемпотентность;
- атомарность и гонки;
- сквозной инвариант «бот никогда не банит» (NR-17.14);
- пауз-семантика, разделение вердикта и применения прохода;
- возврат оплаты как saga; цикл чек → reject → новый чек;
- приватность карточки и /legal; гейт по состояниям для сообщений через Бота;
- whitelist cache-miss и bootstrap; аудит; компенсирующие операции (undo);
- Fail-safe сводку и полный список NR-инвариантов Б17;
- матрицу «команда × состояние»;
- матрицу «команда × роль»;
- патч v3.3 → v3.4 (выжимка, дополнения к матрицам, новые NR);
- единый YAML-контракт `block_17` (26+ КБ, машиночитаемый — переносится байт-в-байт).

Резать это вручную без чётких grep-проверок — гарантированная потеря строк, поэтому
работа выполнена по правилу нулевых потерь и с контролем «до» / «после».

## Правило нулевых потерь (обязательно)

Перед коммитом нарезки должны быть выполнены **все восемь проверок**:

1. Сумма заголовков `^#{1,2} ` по всем `17/17-*.md` **+** число заголовков в новом
   индексе `17-author-panel.md` **>=** 27 (было 27 в исходнике; можно добавить локальный
   заголовок раздела, но нельзя потерять исходный).
2. Число строк матрицы «команда × состояние» до и после — одинаковое.
3. Число строк матрицы «команда × роль» до и после — одинаковое.
4. Все NR-инварианты Б17 (v3.4 включает NR-17.1…23) присутствуют в `17-06-invariants.md`
   или в `17-09-patch-v3-3-to-v3-4.md`.
5. YAML-контракт `block_17` перенесён в `17-99-yaml-full.md` целиком, без сокращений и без
   удаления комментариев (открывающий тег yaml и закрывающий тег на месте).
   Размер `17-99-yaml-full.md` >= 26 000 байт (это дословный YAML, а не выжимка).
6. Все ссылки в новых файлах ведут на реальные пути.
7. Верхний файл `17-author-panel.md` после нарезки содержит только вводную и оглавление;
   содержательных норм, которых нет в частях, там нет.
8. `bash tools/checks.sh` проходит зелёным.

## Порядок работ

1. Создать ветку `agent/block17-split` (или продолжить в текущей `agent/miniapp-first-alignment`,
   если правка идёт одним PR с остальными).
2. Сделать бэкап исходника: `cp architecture/17-author-panel.md /tmp/17_before.md`.
3. Создать 11 файлов в `architecture/17/` по этому протоколу (тексты — из исходника, без
   переформулирования; YAML — байт-в-байт из строк 293–761 исходника).
4. Заменить целиком `architecture/17-author-panel.md` на новый индекс.
5. Прогнать восемь проверок из раздела «Правило нулевых потерь».
6. Обновить строку Блока 17 в [CANONICAL-SOURCES.md](CANONICAL-SOURCES.md) на «нарезан по протоколу».
7. Прогнать `bash tools/checks.sh` — должно быть 15/15 зелёных, включая
   `seventeen_split_guard` («папка 17/ существует и протокол на месте»).

## Финальная сверка (grep-проверки для этого PR)

```bash
# 1. Заголовков верхнего уровня в новом индексе — не более 5 (# + ##)
grep -cE '^#{1,2} ' architecture/17-author-panel.md

# 2. Все 11 файлов частей на месте
ls architecture/17/ | wc -l   # ожидание: 11

# 3. Ни один файл частей не пуст
find architecture/17 -type f -size 0

# 4. YAML-контракт присутствует одним куском в 17-99
grep -c '^```yaml' architecture/17/17-99-yaml-full.md   # ожидание: 1

# 5. YAML-контракт перенесён дословно (размер >= 26 КБ)
wc -c architecture/17/17-99-yaml-full.md   # ожидание: >= 26000

# 6. bash tools/checks.sh проходит зелёным (15/15)
bash tools/checks.sh
```
